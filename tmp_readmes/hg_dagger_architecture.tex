\vspace{6mm}
{\large\bfseries Per-frame dataset columns (converter output)}
\vspace{2mm}

\begin{itemize}[itemsep=3mm, topsep=1mm, leftmargin=8mm]
\item \textbf{\texttt{intervention}} (int64) -- Causal fill of T10: \texttt{INFERENCING}$\to$0, \texttt{PAUSED}$\to$1, else $-1$ (also $-1$ during leader retargeting -- that's the clutch, not a human command). Only the $-1$/0 half is reliable today; the 1 case needs T4$\to$T5 rewiring (pending).
\item \textbf{\texttt{sample\_weight}} (float32) -- Matches Larchenko's LeHome Challenge weighting exactly (arXiv:2606.27163 \S9.10, Fig.\,17): human frames \textbf{2.0}, autonomous baseline \textbf{0.3}, ramping to \textbf{0.0} over the 5s before a takeover. Excluded frames stay at 1.0.
\item \textbf{\texttt{reward}} (int64) -- 1 from \texttt{success\_frame} onward on \texttt{outcome=SUCCESS} episodes, else 0.
\item \textbf{\texttt{done}} (bool) -- True on the final frame of the episode only.
\item \textbf{\texttt{task\_index} / \texttt{subtask\_index}} (int64) -- Mapped per-frame from \texttt{episode\_info.json}'s \texttt{segments} array (each with its own \texttt{frame\_duration} range and \texttt{sub\_task\_instruction}) via existing converter logic (\texttt{\_assign\_subtask\_indices}). For a continuous online-RL take this previously always produced exactly one segment spanning the whole episode -- every frame got whichever instruction was set last, regardless of what was actually happening for most of the take. \texttt{instruction\_change\_log} (see T19) now drives splitting that single segment into one correctly-timed sub-segment per real instruction change. The episode's top-level \texttt{task\_instruction} (the overall task, e.g. "Screw the orange bolt into the hole using the driver.") is a separate, stable field -- it is not derived from the live-changing per-phase instruction, since that field gets overwritten on every T19 click.
\end{itemize}
